# 티켓 컨텍스트 참조

사용자가 작업을 요청하면 AI가 프로젝트를 확인하고 필요한 문서·섹션을 티켓 초안의 `context_refs`에 넣는다. 사용자가 경로를 수동으로 고를 필요는 없으며, 승인 전에 티켓 내용과 함께 검토할 수 있다. 이 기능은 기존 개발·기획·설계 티켓 모두에서 공용으로 사용한다.

## 승인할 초안

기존 request create/revise의 plan-file에 다음 필드를 추가한다. 생략하면 기존 파일명 관련도 기반 선택을 유지한다. 승인된 기존 계획에는 필드를 자동 추가하거나 지문을 재작성하지 않는다.

```json
{
  "ticket_id": "concept-options",
  "project_id": "steam-project",
  "ticket_kind": "planning",
  "goal": "후보별 제작 범위를 비교한다",
  "context_refs": [
    {"path": "docs/concept-notes.md", "section": "제작 제약"},
    {"page_id": "123456", "version": 3, "max_age_minutes": 60}
  ]
}
```

위 예시는 필드 설명용이며, 실제 기획 티켓에는 deliverables, 수용 기준과 실행 단계도 필요하다. [기획·설계 티켓 가이드](PLANNING_TICKETS.md)를 함께 본다.

- 최대 10개 필수 참조를 지정한다. 같은 문서/페이지의 중복 참조는 거부한다. 여러 섹션이 필요하면 문서 전체를 참조한다.
- 로컬 경로는 프로젝트 기준 `docs/` 아래 Markdown 또는 `AGENTS.md`, `README.md`다. 임의 코드·설정·비밀 파일은 참조할 수 없다.
- `section`은 Markdown의 `#` 형태 제목을 정확히 지정한다. 하위 제목은 포함하고 다음 같은 레벨/상위 제목에서 끝낸다. 코드 블록 속 제목은 무시한다. 없는 제목·중복 제목은 차단한다. Setext/HTML 제목 파싱은 지원하지 않는다.
- 핵심 지침·계획·개요·README는 일부 섹션만 참조할 수 없고 항상 전체를 유지한다.
- 선택적으로 `sha256`에 파일 원본 바이트의 소문자 SHA-256을 넣어 승인 시점 내용까지 고정한다. 섹션 밖 수정도 전체 파일 해시가 달라지면 차단한다. 해시를 생략하면 현재 내용을 읽으며 승인 당시 내용과 동일하다는 보장은 하지 않는다.
- 경로·섹션·해시·페이지 버전·허용 경과 시간은 계획 지문과 실행 상태에 결속된다. 승인 후 변경하면 초안을 다시 검토·승인해야 한다.

## Confluence 캐시의 의미

`page_id`는 프로젝트 연결 설정의 `context_page_ids`에 등록된 페이지여야 한다. `version`은 필수 양의 정수이며, `max_age_minutes`는 1~1440분, 기본 1440분이다. 현재 프로젝트·사이트·클라우드·공간에 결속된 로컬 스냅샷만 사용한다.

1. 필요한 페이지가 없거나 지정 버전과 다르거나 조회 후 허용 시간을 넘기면 실행을 차단한다.
2. 기존 `node tools/harness-cli/index.js atlassian context PROJECT_ID`로 연결된 페이지를 다시 읽는다. MCP 우선/opt-in REST 경로는 그대로다.
3. 갱신된 버전이 티켓과 다르면 새 버전을 확인하고 초안을 다시 승인한다. 자동으로 버전 고정을 풀지 않는다.

**캐시 경과 시간과 지정 버전 일치를 검사하는 것이며, 실행 시 서버의 최신 버전을 확인하는 기능은 아니다.** 캐시 조회 이후 서버에서 수정됐을 가능성은 남는다. 번들에도 해당 한계를 명시한다. 네트워크 호출을 매 시도마다 추가하거나 Confluence 문서를 자동 수정하지 않는다. Confluence 본문은 기존 storage 표현 전체를 읽으며 HTML 섹션 추출은 하지 않는다.

## 대화형·CLI·API 실행

승인 계획의 티켓으로 번들을 미리 확인할 수 있다.

```sh
node tools/harness-cli/index.js project context steam-project --bundle --request REQUEST_ID --ticket TICKET_ID --json
```

- 두 ID를 함께 지정하고, 티켓의 프로젝트가 요청 프로젝트와 일치해야 한다. DRAFT 미리보기는 승인이나 실행 허가가 아니다.
- API runner는 매 시도 전에 참조를 다시 확인한다. 누락·변경·노후화는 AI 호출이나 무의미한 재시도 없이 BLOCKED와 기존 실패 알림으로 연결한다.
- 대화형 작업의 `execution review-ready`도 동일한 참조 검사를 적용한다. 문서 참조 검사 자체가 코드 검증이나 사용자 내용 수락을 대신하지 않는다.
- 기본 티켓 번들은 64KB/12파일이다. 필수 지침과 명시 참조는 파일 수보다 우선하되 총 바이트 예산은 넘지 않는다. 필수 자료가 안 들어가면 생략하고 성공하지 않고 실패한다.
- `--full-context`도 승인된 참조의 해시·누락·버전 검사를 우회하지 않는다.
- 출력에는 선택된 경로·섹션·원본 SHA-256·선택 바이트·페이지 버전·조회 시각·생략 이유가 남는다. 토큰 추정은 실제 과금과 다르다.
- 모든 프로젝트/원격 문서는 계속 `untrusted-project-input`이다. 정책 변경, 도구 권한, 비밀 접근이나 Git 승인을 부여하지 않는다. 위험 패턴 탐지는 완전한 프롬프트 인젝션 방어가 아니다.

## 검증과 한계

회귀 테스트는 안전 경로, 섹션 선택, 핵심 지침 보존, 예산 제한, 승인 변조, 로컬 해시 변경, Confluence 버전·조회 경과 시간·연결 변경, CLI 미리보기와 AI 호출 전 차단을 검증한다. 임시 Git/worktree는 실제로 만들지만 모델·알림·Confluence 응답은 모의다. 이 결과는 실계정 접근이나 모델의 자료 이해 정확도를 보증하지 않는다. 자동 의미 검색·벡터 DB·동적 그래프 런타임은 추가하지 않았다.
